# 테스트

프로젝트 루트에서 실행합니다.

```sh
yarn test
yarn test --test-name-pattern="alarm"
node --test tests/planner/input.test.cjs
node --test tests/notifications/*.test.cjs
```

전체 실행은 `run.cjs`가 하위 폴더의 `*.test.cjs`를 찾아 Node 테스트 러너에 전달합니다. 새 테스트 파일을 추가할 때 실행 목록을 수정할 필요가 없습니다.

| 폴더             | 검증 대상                                                     |
| ---------------- | ------------------------------------------------------------- |
| `planner/`       | 일정 규칙, 입력, 선택, 복사, 날짜 이동, 시간·알람 편집        |
| `notifications/` | 알림 계획, 권한, 최초 실행, 설정 저장, 예약 동기화, 알림 화면 |
| `settings/`      | 설정 액션                                                     |
| `data/`          | 저장 큐, DB 마이그레이션, 백업·복원, 내보내기                 |
| `ui/`            | 키보드와 입력 영역 처리                                       |
| `support/`       | TS 로더, 모듈 모킹, 컴포넌트 트리 탐색, 기능별 테스트 환경    |

`support/planner.cjs`와 `support/notifications.cjs`는 네이티브 의존성을 모킹한 뒤 검사할 모듈을 불러옵니다. 각 테스트 전에 데이터와 UI 상태를 초기화합니다. 변경 가능한 상태는 `state`로 접근하고, 렌더링 도우미는 필요한 것만 가져옵니다.

모듈 모킹은 각 테스트 파일의 별도 프로세스 안에서 사용합니다. 서로 다른 환경이 필요한 테스트를 하나의 프로세스로 합치거나 파일 단위 격리를 끄지 않습니다. 컴포넌트 테스트는 콜백과 상태 전이를 검증하며, 실제 터치·키보드·OS 권한 동작은 Android/iOS 기기에서 확인합니다.
